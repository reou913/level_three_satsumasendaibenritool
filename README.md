# 薩摩川内くらしの便利帳

薩摩川内市の市民が、困ったときにぱっと調べられる情報をまとめたサイトです。
GitHub Pages で公開し、「暮らしの要望」の投稿だけ Supabase を使います。

## 載せているもの

| 項目 | 中身 | データ |
| --- | --- | --- |
| 緊急・相談の電話番号 | 119、110、#8000 など。押すと電話がかかる | `data/emergency.json` |
| 夜間・休日の病院 | 今月の救急当番医のページへのリンク、受診の時間や注意 | `data/hospital.json` |
| 保育園・幼稚園 | 54か所。名前・町名で検索、種類と地域でしぼり込み | `data/childcare.json` |
| 子育て | 地域子育て支援センター8か所、児童クラブなどのリンク | `data/kosodate.json` |
| ごみの出し方 | 本土と甑島の出し方、町名で探せるカレンダー（PDF）、分別ハンドブック | `data/gomi.json` |
| 暮らしの要望 | ニックネーム・分野・内容だけで投稿。管理者が確認してから公開 | Supabase |
| 市への正式な窓口 | ご意見・お問い合わせなどへのリンク | `data/requests_links.json` |

- 救急当番医は日によって変わるので、一覧は載せず、ページへのリンクだけにしています。「今月の救急当番医」のリンクは、開いた日の年月に自動で変わります。
- ごみの地区別カレンダーは、PDFの中身は読み取らず、リンクだけにしています。
- どのデータにも、元のページのURLと確認日が入っています。

## ファイルの構成

```
index.html                 サイト本体（市民が見るページ）
admin.html                 要望の管理ページ（管理者だけが使う）
config.js                  Supabase の設定（ここだけ書きかえる）
data/*.json                表示するデータ
supabase/setup.sql         要望のテーブルと安全ルール（RLS・GRANT）を作るSQL
sources.md                 データの出どころ（どのページから取ったか）
README.md                  この説明
```

## Supabase の設定

### 1. テーブルと安全ルールを作る

1. Supabase のプロジェクトを開き、左のメニューの「SQL Editor」を開く
2. `supabase/setup.sql` の中身を全部コピーして貼り付け、「Run」を押す
3. 左の「Table Editor」に `requests` と `admins` ができていれば成功

このSQLでは、次のように決めています。

| だれ | できること |
| --- | --- |
| ふつうの人（ログインなし） | 投稿する（確認待ちとしてだけ）、公開になった要望を読む |
| 管理者（ログインして、admins に登録した人） | すべて読む、公開・非公開を切り替える、消す |
| だれも | ほかの人の投稿の中身を書きかえる |

投稿できる項目は「ニックネーム・分野・内容」の3つだけです。状態（確認待ち／公開）は送れないので、だれが投稿しても必ず「確認待ち」から始まります。

### 2. 管理者を作る

1. 左のメニューの「Authentication」→「Users」→「Add user」→「Create new user」
2. 管理者のメールアドレスとパスワードを入れて作る（「Auto Confirm User」にチェック）
3. 「SQL Editor」で、次の1行のメールアドレスを書きかえて実行する

```sql
insert into public.admins (user_id)
  select id from auth.users where email = 'あなたのメールアドレス'
  on conflict do nothing;
```

### 3. 知らない人がアカウントを作れないようにする

「Authentication」→「Sign In / Providers」（または「Providers」→「Email」）で、「Allow new users to sign up」をオフにします。
アカウントを作れても admins に入っていなければ何もできませんが、念のため閉じておきます。

### 4. config.js に書く

「Project Settings」→「API Keys」（または「Data API」）で、次の2つをコピーして `config.js` に書きます。

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://xxxx.supabase.co",
  SUPABASE_KEY: "公開用の鍵（anon key / publishable key）"
};
```

- 公開用の鍵は、GitHub に上げても大丈夫です。データは RLS で守られています。
- **service_role の鍵（secret key）は、ぜったいに書かないでください。** まちがえて書いたときは、ページが動かず注意が出るようにしてあります。

## 公開する

1. 新しいリポジトリ（Public）に、このフォルダの中身をすべてアップロードする
2. 「Settings」→「Pages」で、Branch を `main`、フォルダを `/(root)` にして「Save」
3. 数分待ってから、表示された URL を開く

## 公開したあとの確認

ログインしていない状態（ふだんのブラウザ）で確かめます。

- [ ] スマホで電話番号を押すと、電話の画面になる
- [ ] 要望を投稿すると「受け付けました」と出る
- [ ] 投稿した要望は、すぐには一覧に出ない
- [ ] 管理者のページ（`admin.html`）でログインすると、確認待ちに出ている
- [ ] 「公開する」を押すと、便利帳のページに出る
- [ ] 管理者のページでログインしていないときは、何も見えない
- [ ] 内容に電話番号やメールアドレスを書くと、送れずに注意が出る

さらに安全を確かめたいときは、Supabase の「Advisors」→「Security Advisor」を開き、注意が出ていないか見ます。

## データを直すとき

- `data/` の JSON をそのまま書きかえます。
- 直したら、その項目の `checked`（確認日）を、確かめた日付（例：`2026-12-01`）にします。
- 元のページを見て確かめていないリンクは `checked` を空（`""`）にしておくと、ページに「未確認」と出ます。
